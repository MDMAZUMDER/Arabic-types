# Database Schema

## Arabic Typing Learning App

**Status:** Logical draft v1.0\
**Purpose:** Persist curriculum, learner progression and exercise
reports. Physical SQL/NoSQL design depends on the selected stack.

## 1. Data principles

-   Store only data needed for the three agreed feature groups.
-   Keep curriculum content separate from learner attempts.
-   Store enough attempt detail to calculate and display reports.
-   Do not store audio/pronunciation data in the current scope.
-   Use stable IDs rather than relying on display text as identifiers.

## 2. Entities

### `curriculum_stage`

  -----------------------------------------------------------------------
  Field                   Type                    Notes
  ----------------------- ----------------------- -----------------------
  `id`                    string                  Primary key

  `order_index`           integer                 Sequential order

  `title`                 string                  Stage name

  `stage_type`            enum                    `letters`,
                                                  `combinations`,
                                                  `small_words`,
                                                  `medium_words`,
                                                  `long_words`,
                                                  `short_sentences`,
                                                  `long_sentences`

  `is_active`             boolean                 Whether stage is
                                                  available in content
  -----------------------------------------------------------------------

### `exercise`

  Field            Type      Notes
  ---------------- --------- ---------------------------------------------
  `id`             string    Primary key
  `stage_id`       string    References `curriculum_stage.id`
  `order_index`    integer   Exercise order
  `target_text`    string    Arabic target text
  `content_type`   enum      `letter`, `combination`, `word`, `sentence`

### `learner_progress`

  Field                   Type       Notes
  ----------------------- ---------- ------------------------------------------
  `id`                    string     Primary key (or fixed local learner key)
  `current_stage_id`      string     Current stage
  `current_exercise_id`   string     Current exercise
  `guided_unlocked`       boolean    Guided mode availability
  `hint_unlocked`         boolean    Hint mode availability
  `test_unlocked`         boolean    Test mode availability
  `updated_at`            datetime   Last progress update

### `exercise_attempt`

  -----------------------------------------------------------------------
  Field                   Type                    Notes
  ----------------------- ----------------------- -----------------------
  `id`                    string                  Primary key

  `exercise_id`           string                  Exercise attempted

  `mode`                  enum                    `guided`, `hint`,
                                                  `test`

  `started_at`            datetime                Attempt start

  `completed_at`          datetime/null           Completion time

  `elapsed_ms`            integer                 Duration

  `target_char_count`     integer                 Number of target
                                                  characters

  `correct_count`         integer                 Correct accepted
                                                  characters

  `mistake_count`         integer                 Incorrect keypresses

  `is_clean_completion`   boolean                 True only if completion
                                                  meets no-mistake rule
  -----------------------------------------------------------------------

### `attempt_mistake`

  Field              Type       Notes
  ------------------ ---------- -------------------------------------
  `id`               string     Primary key
  `attempt_id`       string     References `exercise_attempt.id`
  `expected_char`    string     Character learner should have typed
  `pressed_char`     string     Character actually pressed
  `position_index`   integer    Target position
  `occurred_at`      datetime   Mistake timestamp

## 3. Derived report values

-   `accuracy_percent = correct_count / (correct_count + mistake_count) * 100`,
    if denominator is greater than zero.
-   `characters_per_minute = correct_count / (elapsed_ms / 60000)`, if
    elapsed time is greater than zero.
-   Most-mistyped letters are grouped from
    `attempt_mistake.expected_char` or `pressed_char`; choose and label
    the interpretation clearly. Recommended report: show the expected
    character the learner struggled to enter, and optionally the wrong
    key pressed.
-   Avoid division by zero; display an appropriate placeholder when no
    input/time exists.

## 4. Progress rules

-   A clean completion is an attempt completed without mistakes.
-   Mode unlocks and stage unlocks are determined by the rules in
    `STATE.md`.
-   Do not unlock content from an attempt with `mistake_count > 0`.
-   If a learner retries, retain the prior attempt record for history;
    do not overwrite it.

## 5. Indexes and constraints

-   Index `exercise.stage_id, exercise.order_index`.
-   Index `exercise_attempt.exercise_id, mode, completed_at`.
-   Index `attempt_mistake.attempt_id`.
-   Enforce valid enum values and non-negative counters.
-   Ensure each attempt references an existing exercise.

## 6. Open decisions

-   Exact database engine and physical schema.
-   Whether multiple learner profiles are supported.
-   Whether report history is retained indefinitely or capped.
-   Whether corrections/backspace affect accuracy; recommended policy is
    documented in `PRD.md` and must be finalized before release.

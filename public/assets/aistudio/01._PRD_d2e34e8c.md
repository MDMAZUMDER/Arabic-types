# Product Requirements Document (PRD)

## Arabic Typing Learning App

**Status:** Draft v1.0\
**Platform:** Native Android app (Kotlin + Jetpack Compose)\
**Product focus:** Learn Arabic typing through structured practice and a
game-inspired interface.

## 1. Product goal

Help a learner build Arabic keyboard typing skill progressively, from
individual letters to words and sentences. The app must keep the learner
at the current learning step until the required exercise is completed
without mistakes.

## 2. Scope: the three agreed features

### Feature 1 --- Three learning modes

1.  **Guided Mode**
    -   Show the target text.
    -   Highlight the next required Arabic key on the built-in keyboard.
    -   After a correct keypress, highlight the next required key.
    -   A mistake does not advance the learner.
2.  **Hint Mode**
    -   Show the target text, but do not highlight the next key before
        an error.
    -   If the learner makes a mistake, reveal/highlight the correct key
        as a hint.
    -   A mistake does not advance the learner.
3.  **Test Mode**
    -   Show the target text.
    -   Do not highlight keys or provide hints.
    -   Record the learner's result.
    -   A mistake does not count as a successful completion.

**Unlock rule:** Mode 2 becomes available after the learner completes
the relevant Guided Mode exercise without mistakes. Mode 3 becomes
available after the learner completes the relevant Guided and Hint
exercises without mistakes. Exact attempt/retry policy can be tuned
during implementation, but no error may be treated as a successful
completion.

### Feature 2 --- Step-by-step curriculum

Learning order: 1. Individual Arabic letters. 2. Short combinations
using learned letters. 3. Small words. 4. Medium words. 5. Longer/more
difficult words. 6. Short sentences. 7. Longer sentences.

-   Teach one step at a time.
-   Do not unlock the next step until the current step meets its
    completion rule.
-   If the learner makes a mistake, keep them on the current
    exercise/stage and let them retry.
-   Exercises should use previously introduced material where practical.

### Feature 3 --- Mistake and typing-speed report

After an exercise/test, show: - Total characters attempted. - Correct
characters. - Incorrect characters. - Accuracy percentage. - Typing
speed (characters per minute; optionally words per minute if a
consistent word-count convention is defined). - Which Arabic
letters/keys were mistyped most often. - Time taken. - Best result /
previous result comparison only if this can be shown from saved attempt
history.

Suggested calculation: -
`accuracy = correct_characters / total_attempted_characters * 100` -
`characters_per_minute = correct_characters / elapsed_minutes` - Count
an incorrect keypress as a mistake. Do not silently count a wrong key as
correct. - Define treatment of backspace/corrections consistently in
implementation. Recommended: retain the mistake count even if the
learner later corrects the character; calculate final accuracy from the
recorded keypresses or explicitly document a different policy before
release.

## 3. Keyboard

-   Provide an in-app Arabic keyboard.
-   Use a familiar Arabic layout inspired by common mobile keyboards,
    without copying proprietary artwork or branding.
-   Highlight states must be visually clear and accessible.
-   The keyboard must respond to touch input and display the typed
    result.

## 4. UX and visual direction

-   Professional, polished, game-inspired learning UI.
-   Use level/progress presentation and restrained animation as visual
    treatment, not as extra product features.
-   Avoid childish/cartoon styling and generic template appearance.
-   Keep screens consistent, readable, responsive on small Android
    screens.
-   Support light and dark themes if feasible within the chosen
    implementation.
-   Arabic text and right-to-left layout must render correctly.

## 5. Explicit exclusions for current scope

-   No pronunciation lessons.
-   No audio or voice features.
-   No extra game systems such as coins, leaderboards, multiplayer,
    daily quests, avatars, or social features.
-   Do not add features beyond the three agreed feature groups without
    approval.

## 6. Acceptance criteria

-   The built-in keyboard can enter Arabic characters.
-   Guided Mode highlights the next required key and advances only on a
    correct keypress.
-   Hint Mode does not pre-highlight the next key, but provides the
    agreed hint after a mistake.
-   Test Mode provides no key highlighting or hints.
-   An incorrect input never unlocks the next learning step.
-   Curriculum stages unlock sequentially after successful completion.
-   The report displays mistake count, speed, and accuracy with
    documented calculations.
-   No pronunciation/audio functionality appears in the current release.


## 7. Initial technical direction
- Native Android app using Kotlin and Jetpack Compose.
- In-app Arabic keyboard implemented as a custom Compose UI.
- Room for local curriculum progress and attempt history.
- DataStore for app preferences.
- MVVM + Repository architecture.
- No backend or cloud synchronization in the initial release.
- See `04. STACK.md` for the technology decisions and version policy.

# Design Tokens

## Arabic Typing Learning App

**Status:** Proposed v1.0 --- visual values are starting points, not
final brand decisions.

## 1. Visual direction

Professional, calm, modern, game-inspired. The interface should feel
like a carefully designed learning product, not a childish game or a
generic AI template.

## 2. Color tokens

simply invert colors.

## 3. Typography

-   Use a high-legibility Arabic UI font available and licensed for app
    distribution.
-   Use a separate Latin-capable UI font if needed.
-   Arabic practice text should be larger than surrounding labels.
-   Use consistent type scale: display, heading, body, label, caption.
-   Verify Arabic glyph shaping, diacritics (if included in lesson
    content), and RTL alignment on actual Android devices.

## 5. Components

-   **Primary button:** strong contrast, clear label, minimum
    comfortable touch target.
-   **Lesson card:** stage title, short progress indicator, current
    status.
-   **Keyboard key:** consistent dimensions and spacing; clear
    pressed/highlighted state.
-   **Highlighted key:** use both color and a non-color cue
    (outline/glow/scale) so it remains identifiable.
-   **Error feedback:** brief, clear, non-punitive; never move the
    learner forward.
-   **Report metric:** prominent number, concise label, optional
    explanatory caption.
-   **Progress indicator:** communicates current curriculum position
    without implying unearned completion.

## 6. Motion

-   Use short, restrained transitions for correct-key feedback and
    progress changes.
-   Avoid excessive bouncing, confetti, flashing, or long animations.
-   Motion must not delay typing or interfere with accessibility.

## 7. Layout and accessibility

-   Mobile-first; support narrow Android screens.
-   Arabic content uses RTL; app navigation and mixed-language content
    must be tested.
-   Maintain readable contrast and scalable text.
-   Touch targets should be comfortable and separated enough to reduce
    accidental key presses.
-   Do not rely on color alone to communicate correctness or key
    highlighting.

## 8. Design constraints

-   No extra game mechanics are introduced by this design system.
-   Level/progress visuals are presentation of the agreed step-by-step
    curriculum, not a separate reward economy.
-   Do not use proprietary Gboard assets, logos, or exact branded
    artwork.
